# ai-exam PRD — 신입사원 AI 역량 시험

> 2026-10-14 기준 · Docs 문서 "ai-exam PRD"를 Markdown으로 내보낸 파일입니다.

## 개요

ai-exam은 신입사원의 생성형 AI 활용 역량을 진단하는 웹 시험입니다. 응시, 객관식 자동 채점, AI 서술형 1차 채점, 담당자 확정, 개인 리포트, 부서 단위 분석까지 한 서비스에서 처리합니다.

- **현재 상태:** 구축 6단계와 1차 파일럿(12명 초대, 10명 응시)을 마쳤습니다. 파일럿 결과로 문항 세트 v2, Power BI 내보내기, 응답 신뢰도 개선을 운영 서비스에 반영했습니다.
- **스택:** Next.js 16, Supabase(Postgres), Claude API, Vercel
- **저장소:** [pgp217/ai-exam](https://github.com/pgp217/ai-exam)

## 문제 정의

신입 교육 담당자가 "누구에게 무엇을 먼저 가르칠지" 판단할 근거가 없고, 그 근거를 만드는 서술형 채점은 사람이 하기에 부담이 큽니다.

| 구분 | 내용 | 근거 |
| --- | --- | --- |
| WHO | 기수별 AI 교육을 기획하는 신입 교육 담당자, 서술형을 채점하는 담당자, 자기 수준을 알고 싶은 신입사원 | 파일럿 인터뷰: 응시자는 리포트에서 "동기 중 내 위치"를 가장 먼저 봄 |
| WHY | 자기평가나 일괄 교육으로는 실제 역량을 알 수 없고, 서술형을 사람이 한 명씩 채점하면 시간이 들고 점수가 흔들림 | 파일럿에서 자기평가가 실제보다 높음: 결과 검증 +26, 윤리·보안 +22 |
| WHY AI | 서술형을 기준별로 읽고 근거 문장을 찾는 일은 규칙으로 할 수 없음. AI가 초안과 인용을 만들고, 확정은 담당자가 함 | 실측 1인당 약 23초, 약 $0.15 (7건 중앙값) |

## 목표와 성공 지표

목표는 교육 우선순위를 역량 데이터로 정하게 만드는 것이고, 그 데이터가 믿을 만한지를 숫자로 확인합니다.

| 지표 | 기준 | 1차 파일럿 결과 |
| --- | --- | --- |
| 응시율 | 80% 이상 | 83% (12명 중 10명) |
| 문항 변별력 | 정답률 90% 이상 문항이 적을 것 | 24문항 중 19문항 (v2로 개선) |
| 문항 이해도 (설문 5점 척도) | 3.5 이상 | 4.8 |
| 오류 신고 | 같은 오류 2건 미만 | 0건 |
| 채점 정확성 | 독립 재계산 불일치 0건 | 불일치 0건 (실제 파일럿 9건 포함 42건) |
| 채점 시간·비용 | 실측해 기록 (목표치 미정) | 약 23초, 약 $0.15 |

**목표가 아닌 것**

- 시험 결과를 인사 평가나 불이익 판단에 쓰는 것. 결과는 교육 기획에만 씁니다.
- AI가 점수를 확정하는 것. 확정은 항상 담당자가 합니다.
- 채용 시험이나 외부 지원자 평가. 대상은 입사한 신입사원입니다.

## 사용자와 핵심 시나리오

사용자는 세 부류이고, 한 사람의 응시가 채점 담당자를 거쳐 교육 담당자의 판단 자료가 됩니다.

| 사용자 | 하려는 일 | 핵심 시나리오 |
| --- | --- | --- |
| 신입사원 (응시자) | 내 수준과 키울 점 알기 | 메일·문자로 받은 개인 링크로 로그인 없이 40분 응시 → 채점 후 같은 링크에서 등급, 동기 분포, 성장 피드백 확인 |
| 채점 담당자 | 서술형을 빠르고 일관되게 채점 | AI 초안과 인용 근거를 보며 기준별 점수 확정, AI와 다르면 사유 기록 → 성장 피드백 초안을 고쳐 승인 |
| 교육 담당자 | 어느 부서에 어떤 교육을 먼저 열지 결정 | 시험 생성·대상자 등록·안내 발송 → 결과 목록과 문항 분석 확인 → BI 내보내기로 부서×역량 히트맵과 교육 우선순위 확인 |

## 기능 요구사항

아래 기능은 모두 구현해 운영 중입니다. 역량 체계는 교재 11개 장을 상위 3 · 중위 8 · 하위 16 요인으로 나누고, 문항 35개(객관식 24 · 자기평가 8 · 서술형 3)를 모두 하위 요인에 연결합니다.

| 영역 | 요구사항 |
| --- | --- |
| 응시 | 개인 토큰 링크, 안내·동의, 타이머, 바뀐 답만 자동 저장, 마감 자동 제출. 서버가 마감 시각(+60초)을 다시 확인 |
| 자동 채점 | 객관식 채점, 지식·실전 점수, 객관식 40% + 서술형 60%, 8단계 등급, 3×3 유형 |
| 응답 신뢰도 | 신호 5개(빠른 응답+낮은 정답률, 일렬 응답, 자기평가 무변별, 붙여넣기, 짧은 답안). 신호가 있으면 "추가 검토 필요" |
| 서술형 채점 | 제출 직후 AI가 기준별 1~4점과 근거 인용을 작성, 담당자가 확정. 빈 답안은 "미응답"으로 표시하고 0점 |
| 개인 리포트 | 종합 등급, 유형, 강점·약점, 동기 분포(5명 미만이면 숨김), 자기평가 vs 실제, 성장 피드백(승인 후 공개), 복습할 장 |
| 시험 운영 | 시험 생성 마법사, 대상자 엑셀 업로드·검증, 메일·문자 안내문, 재응시(사유 필수, 첫 기록 보관), 응시 후 설문 |
| 분석 | 문항 분석(정답률, 변별도, 보기 분포, KR-20, AI 일치율), 문항 세트 버전 관리 |
| BI 내보내기 | 응시자·역량 점수·역량 CSV 3개(이름·사번 없이 해시 ID), Power BI 6페이지 대시보드 |

## AI 사용 원칙

AI는 사람이 읽고 써야 해서 시간이 드는 일에만 쓰고, 정답이 정해진 일은 규칙으로, 사람에게 영향을 주는 결정은 담당자에게 남깁니다.

| 맡기는 곳 | 하는 일 | 이유 |
| --- | --- | --- |
| AI | 서술형 기준별 채점 초안과 근거 인용, 성장 피드백 초안 | 자유 서술을 기준에 비추어 읽고 문장을 쓰는 일은 규칙으로 할 수 없음 |
| 규칙(코드) | 객관식 채점, 점수 합계와 등급, 신뢰도 신호, 5명 규칙, 빈 답안 처리 | 결과가 매번 같아야 하고 검증할 수 있어야 함 |
| 담당자 | 서술형 점수 확정, 피드백 승인, 신뢰도 최종 판단, 재응시 허용 | 응시자에게 영향을 주는 결정 |

**AI 결과를 그대로 믿지 않는 장치**

- 답안에 실제로 없는 인용은 근거로 쓰지 않고 화면에 경고로 표시합니다.
- 점수 합계는 AI가 아니라 서버가 계산합니다.
- AI와 다른 점수를 확정하면 사유를 받고, 기준별 AI-담당자 일치율을 보여 줍니다.
- 프롬프트 버전을 채점 기록에 함께 저장합니다.

## 비기능 요구사항

개인정보는 최소한만 다루고, 채점 결과는 앱 밖에서 따로 검증합니다.

| 영역 | 요구사항 |
| --- | --- |
| 개인정보 | AI에는 답안만 전송(이름·사번 제외). 비교 인원 5명 미만이면 동기 비교와 BI 집계를 숨김. BI 파일은 해시 ID만 사용 |
| 권한 | 모든 테이블에 RLS. 익명 키는 어떤 테이블도 읽지 못함. 저장·제출·재응시 함수는 서버 키로만 호출 |
| 보안 | 정답 키는 서버 전용 모듈. 응시 링크 페이지는 referrer 미전송·검색 제외. CSV 수식 주입 방지 |
| 정확성 | Python으로 채점 규칙을 따로 구현해 운영 DB 결과를 재계산. 불일치가 하나라도 있으면 실패. 단위 테스트 120개 |
| 기록 보존 | 재응시 시 첫 응시를 지우지 않고 보관. 문항·정답·기준표는 버전별로 관리해 이전 결과는 이전 버전으로 채점 |
| 성능·비용 | 제출 후 서술형 AI 채점 약 23초, 1인당 약 $0.15 (실측 7건 중앙값, 피드백 생성 비용 제외) |

## 한계와 다음 단계

가장 큰 한계는 표본이 10명이고 AI 채점을 독립적으로 검증하지 못했다는 점입니다.

**현재 한계**

- **표본 크기:** 1차 파일럿 응시자는 10명입니다. 문항 통계는 결론이 아니라 가설로 다뤘습니다.
- **AI 채점 검증:** 일치율 90~100%는 담당자가 AI 점수를 보고 확정한 결과라 독립 검증이 아닙니다.
- **부서 분석:** 실제 파일럿에는 부서 정보가 없어, 부서·기수 대시보드는 가상 데이터 202명으로 구축했습니다.
- **범위:** 조직 진단이나 인력 산정 데이터와는 아직 연결하지 않았습니다.

**다음 단계 (순서대로)**

1. **v2 문항으로 2차 파일럿:** 변별력이 좋아졌는지 문항 분석으로 확인합니다.
2. **블라인드 채점 표본:** 담당자가 AI 점수를 보기 전에 먼저 채점해 AI 채점을 독립적으로 검증합니다.
3. **붙여넣기 신호 개선:** 붙여넣은 글이 지문과 같으면 신호에서 뺅니다. 문자열 비교로 충분해 AI를 쓰지 않습니다.
4. **AI 문항 개선 초안:** 문항 분석 결과(정답률, 보기 분포)를 바탕으로 AI가 오답 보기와 지문 수정안을 제안하고, 출제자가 고릅니다.
5. **확정 사유 분석:** 블라인드 채점으로 사유가 쌓이면, AI가 사유를 묶어 채점 기준표 문구 수정을 제안합니다.

열린 질문: 2차 파일럿의 대상 인원과 일정은 아직 정하지 않았습니다.
