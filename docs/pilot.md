# 소규모 파일럿 운영 계획

실제 사람 8~15명이 응시하는 파일럿으로, 데모 데이터로는 알 수 없는 것을 확인한다.

## 1. 확인할 질문

| 질문 | 보는 데이터 |
|---|---|
| 제한 시간 40분이 적당한가 | 응시 시간 분포, 설문 "제한 시간" 평균, 마감 자동 제출 건수 |
| 문항이 무엇을 묻는지 분명한가 | 설문 "문항 이해도", 자유 의견에 나온 문항 번호, 문항별 정답률(너무 높거나 낮은 문항) |
| 실제 답안에서 AI 1차 채점을 믿을 수 있는가 | 기준별 AI-담당자 일치율, 담당자가 점수를 바꾼 기준과 사유 |
| 응시 중 오류가 나는가 | 설문 오류·불편 신고, 재응시 건수와 사유 |
| 리포트와 성장 피드백이 도움이 되는가 | 리포트 공개 뒤 짧은 인터뷰(3~5명) |
| 운영 비용과 담당자 시간은 얼마나 드는가 | Claude 사용량, 1인당 채점 검토 시간 |

## 2. 대상과 개인정보

- **인원:** 8~15명. 신입~3년차 수준의 동료나 지인이고, 직무가 섞이면 좋다. 동기 비교(상위 %)는 채점 완료 5명부터 켜진다.
- **이름·사번:** 실명 대신 별칭도 괜찮다. 사번은 `P-001`처럼 파일럿 번호를 쓴다. 이메일과 휴대폰은 비워 두고, 응시 링크는 메일이나 메신저로 직접 보낸다.
- **동의 (안내문에 반드시 적기):**
  - 응답은 시험 개선에 쓴다.
  - 결과는 개인을 알아볼 수 없는 통계로만 공유한다. 포트폴리오에 쓸 때도 마찬가지다.
  - 원하면 언제든 기록 삭제를 요청할 수 있다.
- **삭제 요청:** 응시 기록이 있는 대상자는 화면에서 지울 수 없다. 요청이 오면 SQL Editor에서 `delete from public.candidates where exam_id = '<파일럿 시험 ID>' and employee_no = 'P-00n';`을 실행한다. 응시, 채점, 결과, 설문, 재응시 보관본이 함께 지워진다.
- **AI 전송:** 서술형 답안만 보내고, 이름과 사번은 보내지 않는다(기존 설계 그대로).

## 3. 준비 (D-3 ~ D-1)

1. Supabase SQL Editor에서 `supabase/migrations/0005_survey.sql`을 실행한다.
2. **시험 관리 → 새 시험**으로 파일럿 시험을 만든다. 데모 시험과 섞이지 않게 반드시 새로 만든다.
   - 기본 설정: 시험명 `[파일럿] 신입사원 AI 역량 시험`, 응시 기간 7일
   - 응시 사이트: 제한 시간 40분, 결과 리포트 공개 켬, **응시 후 설문 받기 켬**
3. 대상자를 엑셀 양식으로 등록한다(사번 `P-001`~, 이름, 소속은 선택).
4. 안내문을 저장한다(아래 초안 참고).
5. **리허설:** 본인용 대상자(`P-000`)로 처음부터 끝까지 한 번 응시한다. 확인할 것:
   - 응시와 제출
   - AI 채점, 담당자 확정
   - 리포트와 설문
   - 확인이 끝나면 `P-000`은 결과 분석에서 뺀다.
6. **시험 열기**를 누른다.

## 4. 운영 (D0 ~ D+6)

- **D0:** 안내문 CSV를 내려받아 각자에게 링크를 보낸다.
- **매일 한 번:**
  - **서술형 채점**에서 "검토 대기"를 확정한다. 점수를 바꾸면 사유를 꼭 적는다. 일치율 분석의 근거가 된다.
  - **설문**에서 오류·불편 신고를 확인한다. 응시를 망친 오류라면 사유를 적고 재응시를 허용한다.
- **D+4:** 미응시자에게 한 번 다시 알린다.

## 5. 마감과 리포트 (D+7 ~ D+10)

1. **D+7:** 응시 기간이 끝나면 남은 서술형을 모두 확정한다.
2. **D+8~D+10:** 결과 목록에서 사람별로 성장 피드백 초안을 확인하고 고친 뒤 **승인하고 공개**한다.
3. 리포트를 본 사람 중 3~5명에게 5분 인터뷰를 한다.
   - 리포트에서 가장 먼저 본 것은?
   - 납득이 안 된 점수가 있었나?
   - 피드백대로 해 볼 만한가?

## 6. 분석 (D+11 ~ D+14)

| 지표 | 계산 | 기준 예시 |
|---|---|---|
| 응시율 | 제출 ÷ 대상자 | 80% 이상 |
| 응시 시간 | 결과의 응시 시간 중앙값·최대 | 최대가 40분에 몰리면 시간 부족 |
| 설문 평균 | 설문 화면 | 이해도 3.5 미만이면 문항 문구 점검 |
| 오류 신고 | 설문 화면 | 같은 오류 2건 이상이면 우선 수정 |
| AI-담당자 일치율 | 서술형 채점 화면(기준별) | 낮은 기준은 채점 기준표 문구 보완 |
| 문항 정답률 | 문항별 정답 비율 (다음 작업인 문항 분석 화면에서 제공 예정) | 90% 이상, 20% 이하 문항은 교체 후보 |
| 비용 | Anthropic Console 사용량 | 1인당 약 $0.13 예상 |

정합성 점검(`scripts/crosscheck.py`)을 돌려 파일럿 결과도 불일치가 없는지 확인한다.

## 7. 결과 정리

개선 과제를 **문제 → 근거(데이터) → 조치 → 반영 여부** 표로 정리한다. 예:

| 문제 | 근거 | 조치 |
|---|---|---|
| E3 '대안 제시' 기준을 AI가 후하게 채점 | 해당 기준 일치율이 가장 낮음, 담당자 하향 조정 n건 | 기준표 2점·3점 구분 문구 구체화, 프롬프트 버전 올림 |

포트폴리오에는 이 표와 핵심 숫자(응시 n명, 일치율, 개선 n건)만 쓰고, 개인을 알아볼 수 있는 내용은 쓰지 않는다.
