## 1. 요인 체계 (상위 → 중위 → 하위)

## 2. 문항 구성 (약 35분)

| 유형 | 수 | 채점 | 측정 |
|---|---|---|---|
| 객관식 (4지선다) | 24 | 자동 | 중위요인당 3문항 → **지식 점수** |
| 자기평가 (5점 척도) | 8 | 점수 미반영 | 중위요인당 1문항 → "내가 본 나" 비교용 |
| 서술형 시나리오 | 3 | AI 1차 → 담당자 확정 | **실전 점수** |

서술형 3문항 (신입 업무 상황):
1. **프롬프트 작성** — "팀장이 신입 OJT 일정표 초안을 부탁했다. AI에 보낼 프롬프트를 써라." (프롬프트 설계)
2. **결과 검증** — AI가 쓴 보고서 단락(수치·출처 포함)을 주고 "의심되는 부분 3가지와 확인 방법을 써라." (결과 검증)
3. **윤리 판단** — "선배가 고객 명단이 든 엑셀을 외부 AI에 올려 정리하라고 한다. 어떻게 하겠는가?" (윤리·보안)

### 서술형 채점 기준표 (문항당 4개 기준 × 1~4점)

예) 문항 1 프롬프트 작성

| 기준 | 1점 | 2점 | 3점 | 4점 |
|---|---|---|---|---|
| 5요소 포함 | 과업만 있음 | 2~3개 요소 | 4개 요소 | 5개 요소 모두 명시 |
| 구체성 | "만들어줘" 수준 | 대상만 구체적 | 대상·분량 구체적 | 대상·분량·기간·제외사항까지 구체적 |
| 출력 형식 | 지정 없음 | 막연한 지정 | 표·목록 등 형식 지정 | 형식+열 구성까지 지정 |
| 보안 고려 | 실명·민감정보 포함 | — | 민감정보 없음 | 민감정보 없음 + 가명 처리 언급 |

문항 점수 = 기준 합(4~16) → 0~100 환산.

## 3. 점수와 등급

- **지식 점수** = 객관식 정답률 (0~100)
- **실전 점수** = 서술형 3문항 확정 점수 평균 (0~100)
- **상위요인 점수**
  - AI 이해 = 해당 객관식 정답률
  - AI 활용 = 객관식 40% + 서술형 1번 60%
  - AI 책임 = 객관식 40% + 서술형 2·3번 평균 60%
- **종합 점수** = 상위요인 3개 평균
- **등급 8단계** (에이치닷과 동일): D 0~30 · D+ 30~40 · C 40~50 · C+ 50~60 · B 60~70 · B+ 70~80 · A 80~90 · A+ 90~100
- 서술형 확정 전에는 결과 상태를 "채점 중"으로 두고 리포트를 공개하지 않는다.

## 4. 신입 AI 유형 (3×3)

가로축 지식 점수, 세로축 실전 점수. 낮음 <50 · 보통 50~75 · 높음 ≥75 (설정에서 변경 가능)

| 실전 \ 지식 | 낮음 | 보통 | 높음 |
|---|---|---|---|
| **높음** | 직관형 활용가 | 실전 성장가 | AI 에이스 |
| **보통** | 경험 학습가 | 균형 성장형 | 지식 탄탄형 |
| **낮음** | AI 입문자 | 기초 학습자 | 이론 우선형 |

유형마다 한 줄 설명, 성장 방향, 추천 교재 장을 둔다.

## 5. 응답 신뢰도 (에이치닷 "자기 응답 신뢰도" 대응)

| 신호 | 기준 (초안) |
|---|---|
| 응답 시간 | 객관식 평균 응답 시간 5초 미만 |
| 일렬 응답 | 같은 보기 번호를 8문항 이상 연속 선택 |
| 자기평가 무변별 | 자기평가 8문항이 모두 같은 값 |
| 서술형 붙여넣기 | 서술형 입력 중 붙여넣기 발생 (외부 AI 답변 복붙 의심) |
| 서술형 분량 | 문항당 50자 미만 |

신호 0개 **신뢰 가능** · 1개 **주의** · 2개 이상 **신뢰 불가**. 관리자 결과 목록에서 필터로 쓴다.

## 6. 결과 리포트 (개인)

1. **종합 결과** — 종합 등급·점수 카드, 지식/실전 점수, 동기 내 상위 %
2. **AI 유형** — 3×3 격자 위 내 위치, 유형 설명과 성장 방향
3. **핵심 키워드** — 하위요인 기준 강점 2개 · 약점 2개
4. **상위요인 결과** — 요인별 등급, 동기 분포 히스토그램 위 내 위치
5. **내가 본 나 vs 실제** — 중위요인별 자기평가와 실제 점수 차이 (과대·과소평가 표시)
6. **AI 피드백** — 서술형 확정 근거와 점수를 바탕으로 생성한 개선 조언 (담당자 확인 후 공개)
7. **복습할 장** — 오답·저득점 하위요인의 교재 링크

## 7. 화면

**관리자**
- 시험 목록
- 시험 생성 마법사: ① 기본설정(시험명, 응시 기간, D-day) ② 응시 사이트 설정(안내 문구, 제한 시간, 결과 공개 여부) ③ 대상자 설정(엑셀 양식 다운로드·업로드, 검색, 필터) ④ 안내문 작성(메일·문자, 매핑 항목 `$이름$` `$시험명$` `$응시 기한$` `$응시 URL$`, 추천 서식, 미리보기 — 실제 발송 없음)
- 결과 목록: 이름, 소속, 사번, 기수, 응시 상태, 채점 상태, 응답 신뢰도, 유형, 등급 + 필터
- 서술형 채점 리뷰: AI 1차 점수·근거(응답 원문 인용)를 보고 기준별 점수를 조정·확정, AI와 다르면 사유 필수
- 개인 리포트 보기

**응시자** (로그인 없이 개인별 응시 링크)
- 안내·동의 → 응시(타이머, 문항 이동, 임시 저장) → 제출 완료 → (공개 시) 리포트

## 8. AI 채점 파이프라인

1. 응시자가 제출하면 서술형 응답마다 채점 작업 생성
2. 서버(API Route)에서 Claude API 호출: 문항, 기준표, 응답을 주고 **기준별 점수 + 근거(응답 원문 인용) + 판정 이유**를 JSON으로 받음
3. `ai_gradings`에 저장 (모델, 프롬프트 버전, 원문 출력 포함) — 확정 점수가 아님
4. 담당자가 리뷰 화면에서 확정 → `final_gradings`에 별도 저장
5. 모든 서술형이 확정되면 결과 계산 → 리포트 공개
6. 지표: AI-담당자 일치율(기준별 점수 일치 비율)을 관리자 화면에 표시

개인정보: AI에는 응답 텍스트만 보내고 이름·사번은 보내지 않는다.

## 9. DB 스키마 (Supabase / Postgres 초안)

```sql
exams            (id, title, starts_at, ends_at, time_limit_min, intro_text,
                  show_result, item_set_version, status, created_at)
candidates       (id, exam_id, employee_no, name, email, phone, department,
                  cohort, joined_at, access_token, invited_at)
items            (id, item_set_version, top_factor, mid_factor, sub_factor,
                  source_chapter, type, prompt, options jsonb, answer, rubric jsonb, sort_order)
attempts         (id, candidate_id, started_at, submitted_at, duration_sec,
                  reliability jsonb, status)
responses        (id, attempt_id, item_id, answer jsonb, response_ms, pasted bool)
ai_gradings      (id, response_id, model, prompt_version, criterion_scores jsonb,
                  score, rationale, evidence jsonb, raw jsonb, created_at)
final_gradings   (response_id PK, grader_id, criterion_scores jsonb, score,
                  override_reason, confirmed_at)
results          (attempt_id PK, factor_scores jsonb, knowledge_score, practice_score,
                  total, grade, ai_type, cohort_percentile, computed_at)
notice_templates (id, exam_id, channel, subject, body)
```

관리자는 Supabase Auth로 로그인, 응시자는 `access_token` 링크로만 접근 (Row Level Security로 분리).

## 10. 개발 단계

1. 문항·채점 기준표 확정, DB 스키마 생성, 시드 데이터(가상 응시자 30명)
2. 응시 화면 + 객관식 자동 채점 + 응답 신뢰도
3. AI 1차 채점 + 담당자 리뷰·확정
4. 개인 리포트 + 관리자 결과 목록
5. 시험 생성 마법사 + 엑셀 업로드 + 안내문 작성
6. 버그 점검·정합성 크로스체크, Vercel 배포, 데모 링크 정리
